# Log — aparelho mobile2

**Data:** 2026-11-11  
**Sessão:** adição de feature

---

## ✅ O que foi feito

- O aplicativo do aparelho compartilhado foi criado em `mobile2`, ao lado do aplicativo de cada funcionário.
- A liberação usa o código gerado no site. A chave de cada empresa fica só no armazenamento seguro do aparelho.
- O reconhecimento facial compara cada empresa separada e, sem internet, guarda a marcação só quando uma empresa reconhece.
- O QR Code continua só com internet. Sem rede a marcação não fica no aparelho.
- O aplicativo do funcionário não foi alterado.

## 📁 Arquivos criados

- `mobile2/` — projeto Flutter do aparelho, com o nome Ponto relógio
- `mobile2/lib/main.dart` — sobe o aplicativo e exige https na versão de produção
- `mobile2/lib/app/app.dart` — tema e indicador de carregamento
- `mobile2/lib/app/router.dart` — liberação na primeira vez e tela de ponto depois
- `mobile2/lib/data/network/device_api.dart` — chamadas do aparelho, sem sessão de funcionário
- `mobile2/lib/data/network/device_vault.dart` — identificador e chaves no armazenamento seguro
- `mobile2/lib/features/device/data/device_flow.dart` — liberar empresa, baixar rostos e registrar ponto
- `mobile2/lib/features/device/data/clock_store.dart` — rostos separados por empresa e fila facial
- `mobile2/lib/features/device/data/face_decision.dart` — uma empresa segue; nenhuma ou mais de uma bloqueia
- `mobile2/lib/features/device/presentation/screens/setup_screen.dart` — digitar o código
- `mobile2/lib/features/device/presentation/screens/home_screen.dart` — os dois botões de registro
- `mobile2/lib/features/device/presentation/screens/qr_punch_screen.dart` — QR Code e selfie
- `mobile2/.env.example` — endereço de exemplo da API
- `mobile2/test/face_decision_test.dart` — decisão de uma, nenhuma ou várias empresas

## ⚠️ Decisões tomadas

- O identificador do pacote Android ficou `com.sistemaponto.sistemaponto_relogio`, diferente do aplicativo do funcionário, para os dois poderem ficar no mesmo celular.
- O modelo `w600k_r50.onnx` e o `.env` com o endereço da rede ficam só na máquina. Não entram no Git.
- A identidade visual foi a mesma do aplicativo do funcionário. Não há login, início da pessoa, solicitações, apuração nem banco de horas.
- Se o servidor responde que o aparelho não está liberado, as chaves locais saem e a tela de código volta.

## 🐛 Problemas encontrados e soluções

- O teste inicial do Flutter apontava para uma tela que este aplicativo não tem. → O arquivo foi removido.
